# 校园有应改造后自查

日期：2026-10-19。

本轮围绕改造代码进行静态检查和可复现的回归测试。先加入失败测试，再修复，检查原有安全、记忆、API、检索和工具流程。没有新增 Agent 或逐次政策回答的模型核验机制。

## 已确认并修复的问题

| 问题 | 修复后的行为 |
|---|---|
| 导入已过期的新版本会归档当前有效版本，造成无适用政策可查 | 过期文件保存为归档状态，不替换现行版本 |
| 只有标题的 Markdown 可以以零块数导入并归档旧版 | 导入前验证存在有效正文；历史零块文档也不能启用 |
| 空白或无可提取文字的 PDF 因页码标记被误认为有正文 | 仅为有文本的页添加页码；无正文返回明确 OCR 提示 |
| 同来源、同版本、同正文但学校或领域不同，被静默当作已成功导入 | 显式拒绝作用域冲突，要求使用不同来源名或版本号；沿用单校设计和既有唯一约束 |
| BM25 权重设为零后，仍会返回零分证据 | 零权重通道不参与召回和融合；没有有效通道时返回空结果 |
| 父向量召回成功、子向量失败时，残留半次向量召回结果 | 可降级模式完整回退到 BM25，并记录失败原因 |
| 索引 manifest 损坏等初始化异常，绕过降级逻辑导致请求失败 | 可降级模式记录错误并使用 BM25；required 模式明确失败 |
| 全量索引重建后，旧实例仍可能向旧 collection 写入 | 写入、删除和计数也刷新 manifest，跟随当前已切换索引 |
| 同一消息重试时，缓存回复的 HIGH 被返回成 LOW，回复模式和 trace 丢失 | 从原 trace 恢复风险、有效风险、回复模式和 trace ID；工具动作继续保持幂等 |
| ACTIVE→MONITORING、MONITORING→RESOLVED 等当轮变化晚一轮影响回复模式 | 优先使用本轮安全产物的新状态，历史快照仅作回退；上下文安全约束同步使用新状态 |
| 高危先回复后检索时，最终可能附上未参与生成的资料 | 候选回复绑定实际使用的上下文 ID；引用和号码来源核实使用该上下文，不使用后来到达的结果 |
| 政策生效日期依赖服务器本地日期，UTC 部署可能延迟八小时 | 统一按 Asia/Shanghai 解释政策日历日期 |

高危可以先生成安全回复，因而不保证每条高危回复都有资料引用；原有工程检查相应改为核对安全模式及“已附证据确实进入生成 prompt”。ContextAgent 的执行检查仍保留。

## 验证结果

- 全量 unittest：99/99 通过，比首轮新增 14 项回归测试。日志：`target/self-review-tests.log`。
- 六组工程 harness：全部通过，包括风险、安全、路由、Skills、RAG、API 和工具队列。日志：`target/self-review-harness.log`，结构化结果：`target/harness/harness-report.json`。
- 校园 mock 端到端冒烟：7/7 通过。日志：`target/self-review-eval.log`，结果：`target/campus-mock-eval.json`。
- Python 编译和 `pip check`：通过。
- Chroma 测试使用实际临时本地索引与确定性测试向量，不调用真实 embedding API；覆盖双层召回、原子重建、失败保留旧索引、损坏 manifest 降级以及旧实例写入。

自查前源码备份：`target/backups/pre-self-review-source.tgz`，不含配置密钥、业务数据库和模型权重。

## 验证范围

本轮使用隔离 SQLite、临时 Chroma 和 mock 模型，没有操作现有 MySQL 业务库、重建正式索引或发送外部预警。没有重跑收费模型接口，上一轮真实模型冒烟结果保留在 `target/campus-real-eval.json`。

真实学校政策尚未提供，政策金额和规则准确性仍需正式资料及人工标注保留集验收；现有 MySQL 的真实迁移与部署联调尚未执行。通过本轮测试不等于证明项目不存在其他缺陷。
