# 校园有应：项目改造方案与实施清单

> 最新调整：所有回复模式（含情绪支持、风险监测和 HIGH）使用真实 SSE 增量输出，学生端不返回来源，管理员逐条查看；CHAT/CONSULT 边界已收紧。以 [本次实现说明](streaming-routing-and-admin-sources.md) 为准，本文保留原阶段记录。

整理日期：2026-10-18

本文保留本次讨论的改造方案和验收基准。2026-10-18 已按建议默认方案完成主要代码改造；实际实现、验证结果及仍待正式学校资料的部分见 [实施结果与接入说明](campus-youying-implementation.md)。文中待确认项是原讨论记录，实施采用的默认值以实施说明为准。

## 1. 产品目标与范围

将 MindBridge 从校园心理支持项目改造为“校园有应——校园资讯与生活支持 AI 助手”。保留现有三类意图、五个 Agent、事件驱动编排、会话记忆和心理安全处理链路。

面向学生提供：

- CHAT：日常闲聊、分享和一般交流。
- CONSULT：依据校内文件回答校规、研究生报销、培养要求、奖助政策和校园服务问题。
- RISK：对危险表达进行独立安全评估，保留原有支持、报告、个案和人工预警能力。

第一阶段聚焦对话与资讯，不引入诉求派单、跨部门审批或办理进度系统。实时食堂菜单、空闲教室、个人报销审批进度等依赖额外数据接口，不作为政策 RAG 的既有能力承诺。

## 2. 已明确方向与待确认项

### 2.1 已明确的改造方向

1. 保留 CHAT / CONSULT / RISK 三分类，将 CONSULT 的主要含义由心理咨询改为校园政策资讯咨询。
2. 保留原有心理安全能力，安全评估覆盖所有输入，而非仅覆盖分类为 RISK 的消息。
3. 不新增专门的政策核验 Agent；第一阶段不额外为每次政策回答调用模型进行事实打分。
4. 政策问答质量主要通过开发阶段的离线评测、人工验收、知识更新后的回归和使用反馈保证。
5. 保留原有回复安全审查；它与政策事实核验是不同职责。
6. RAG 改为父子切块，父块、子块都生成 Embedding。
7. 沿用 MySQL、Redis、Chroma 和现有模型接入方式，不因父子切块引入新的 Agent 框架。

### 2.2 仍待确认，以下建议不等于用户已经确认

| 事项 | 建议默认方案 | 对改造的影响 |
|---|---|---|
| 服务学校 | 单校起步 | 多校需要身份选择和严格的学校过滤 |
| 无明确危险的情绪求助 | 进入 RISK 支持分支，再评估等级 | 需重新定义原 CONSULT 中情绪支持内容的归属 |
| 风险等级 | 保留 LOW / MEDIUM / HIGH | 当前跨轮降级和监测机制依赖三级风险 |
| 正式政策资料 | 使用选定学校的正式文件 | 学校、文件和版本清单尚未提供，不填写真实报销标准 |
| Embedding / 回答模型 | 先沿用配置，用真实问答验证 | 现有心理支持微调模型是否适用，须经评测 |
| 本地规则重排 | 保留开关，对比开启和关闭 | 不作为父子检索必须步骤，默认值由评测决定 |
| 切块尺寸、候选数、融合权重 | 作为实验参数 | 不将讨论中的示例参数当作最佳值 |

## 3. 现有实现基线

以下根据当前代码核对，不代表已运行完整测试或已验证部署状态。

| 模块 | 当前实现 | 改造要点 |
|---|---|---|
| 意图识别 | CONSULT 偏心理支持，校园事务可能被分到 CHAT；存在普通任务关键词快捷规则 | 提示词、快捷规则、异常回退和 mock 同步修改 |
| 回复生成 | 非 CHAT 路径主要使用心理支持提示词与 Skills | 分开政策回答和情绪支持 |
| 报告触发 | `current_risk >= MEDIUM` 或 `intent == CONSULT` | 移除“政策咨询即心理报告”的绑定 |
| 切块 | 空白归一化后，512 字符窗口、64 字符重叠 | 保留文件结构，建立父子关系 |
| 检索 | 向量 + BM25，融合后本地规则重排，默认最终 Top-4 | 扩展为父块和子块双粒度向量检索 |
| 上下文扩展 | 仅最高分块拼接同源前后邻块 | 父子检索路径改为取回父块 |
| 检索改写 | 面向校园心理知识库，最多 60 字符 | 按知识领域改写，保留政策身份与条件 |
| 知识预算 | 默认约 1200 tokens，遇超预算项直接停止 | 改为适配父块的预算策略，避免首项过长导致无正文进入上下文 |
| 安全审查 | 主要检查安全指引关键词、内部标签泄露和监测阶段近况确认 | 继续保留；不宣称已经核验政策事实 |
| 普通记忆 | 会话原文 + 12→8 滚动摘要 | 保留机制，调整摘要和检索使用方式 |
| 安全记忆 | 用户级风险事件与状态，独立持久化 | 保留跨会话继承、复核、人工解除与幂等 |
| 运行恢复 | 运行结束保存 trace | trace 用于审计，并非可恢复执行的检查点 |

## 4. 意图、风险与回复策略

### 4.1 三分类边界

| 类型 | 示例 | 预期处理 |
|---|---|---|
| CHAT | “今天终于交完论文了。” | 自然回应，加载会话记忆 |
| CONSULT | “研究生出差每天的伙食补助是多少？” | 检索适用政策，回答并展示来源 |
| CONSULT | “学校心理咨询中心怎么预约？” | 查询服务信息，不因出现心理词汇就认定危险 |
| RISK | “我最近过得不好，我想自杀。” | 优先安全处理，按既有规则评估并执行后续 |
| 待确认边界 | “压力很大、睡不好，想找人聊聊。” | 建议保留情绪支持能力，进入支持分支后评级 |

RISK 是内部处理入口，不等同于 HIGH；不得向学生直接展示内部风险标签。用户实际危险表达、政策讨论、引用和否定表达应纳入分类回归用例。

### 4.2 业务意图与安全约束分离

- 每轮重新识别用户当下请求，同时独立评估安全状态。
- 保留 `currentRisk / carryoverRisk / effectiveRisk`。
- 历史未解除风险可以约束本轮政策回答，不能因用户换话题或新建会话自动解除。
- 必要时保留原始业务意图用于理解和统计，兼容现有最终意图及安全覆盖机制。
- 正常 CONSULT 选择政策回答提示词；安全状态要求关注时，同时附加对应安全约束。

### 4.3 报告和工具触发

- 普通政策咨询保存消息、检索依据和 trace，不触发心理报告、风险个案或预警。
- 心理报告与工具计划改由明确的安全触发条件决定，保留原有必要能力。
- LOW 情绪支持是否生成独立咨询记录，待确认；不能再通过 CONSULT 标签隐式触发。
- 历史 HIGH 约束不应把每次普通追问都当作新事件重复告警。
- 保留消息、报告和工具任务的幂等规则。

## 5. Agent 编排方案

### 5.1 保留五个角色

| Agent | 改造后职责 |
|---|---|
| UnderstandingAgent | 三分类、主题识别，结合上下文理解当前输入 |
| SafetyAgent | 全输入安全评估、跨轮风险合并、候选正文安全审查 |
| ContextAgent | 会话上下文、领域选择、查询改写、父子检索、来源组装 |
| ResponseAgent | 根据意图、证据和安全约束生成候选正文 |
| CoordinatorAgent | 任务依赖、认领、预算、修改请求和最终采纳 |

### 5.2 主链路

```text
用户输入先保存
  → 检查上下文预算，加载统一 MemorySnapshot
  → 意图识别 + 独立安全评估
  → 按需检索政策或心理支持知识
  → 生成候选正文
  → 沿用现有安全审查
  → Coordinator 采纳
  → 传输已经批准的正文
  → 保存完整回复，维护记忆，按安全条件执行工具计划
```

这里的“+”表示两项工作都需要，不承诺已实现异步并行。当前调度器按选中任务逐个执行；第一阶段不以并发重构为目标。

- CHAT 不强制检索，但必须带入必要历史。
- CONSULT 使用政策证据；依据不足时允许输出澄清问题或覆盖范围说明。
- 高风险支持不等待政策检索成功，保留现有优先安全处理能力。
- 保留“审查绑定当前候选版本”；重写后重新审查。
- 不新增政策事实核验 Agent 或必经的模型核验任务。
- 维持有限调度预算；预算耗尽时使用适配场景的回退文案，不能把失败包装成政策结论。

## 6. 父子切块与双粒度检索

### 6.1 切块规则

- 父块优先对应完整条款、小节或业务主题，不直接把整篇长文件作为父块。
- 父块默认不重叠；过长时按完整子主题继续拆分。
- 子块在单个父块内部生成，优先保持完整句段；长段落才用滑窗和少量重叠。
- 子块不得跨越父块边界；父子重用原文和相邻块重叠是不同概念。
- 文档标题、章节、适用对象等可靠背景可加入检索文本，避免子块脱离语境。
- 表格必须保留表头、单位、对象、注释与数值对应关系。先核对解析结果，再建立索引。
- 其他章节中的通用适用条件不会因父子切块自动补齐，必要时显式关联。

可供实验的起点：子块约 200～350 字符，父块约 600～1200 字符，滑窗子块重叠约 40 字符。条款完整性优先，参数未定稿。

### 6.2 存储与 Embedding

建议新增文档级元数据，扩展现有知识块表：

| 层级 | 建议字段 |
|---|---|
| 文档 | 标题、学校、领域、发布部门、原文链接、发布/生效日期、版本、有效状态 |
| 父块 | 文档 ID、块类型、章节路径、条款/页码、正文、顺序 |
| 子块 | 文档 ID、父块 ID、块类型、正文、顺序、来源位置 |
| 向量记录 | 数据库块 ID、块类型、父块 ID、领域、文档版本/检索所需过滤信息 |

- 父块和子块均生成向量，使用同一个配置的 Embedding 模型。
- 1 个父块包含 N 个子块时，对应 N+1 个向量，不是同一段正文机械复制成两条记录。
- 原文、父子关系在 MySQL 保存，向量在 Chroma 保存。
- 可使用同一 Chroma collection，通过 `chunk_type` 过滤检索；此方案需要扩展当前查询接口。
- Embedding 输入明确拼接所需标题背景，metadata 不会自动参与向量化。
- 沿用 OpenAI-compatible `/embeddings` 接口；默认模型配置是 `text-embedding-3-small`，具体运行配置另行确认。
- 更换 Embedding 模型后重建文档向量；不能混用不兼容模型空间。

### 6.3 候选召回与父块归并

建议第一阶段保留三路候选，父块 BM25 暂不额外增加：

```text
结合上下文改写查询，确定领域和适用过滤条件
  ├─ 父块向量召回
  ├─ 子块向量召回
  └─ 子块 BM25 召回
       → 统一映射到父块
       → 同一路内按父块聚合，例如取最高子块分数
       → 进行跨路分数归一化和融合，保留命中来源
       → 按父块去重、排序
       → 在预算内读取并组装父块正文
       → 交给 ResponseAgent
```

- 每路有独立候选配额，避免父块和子块挤占同一个 Top-K。
- 最终返回数量以去重后的父块计，不把多个同父子块当作多份证据。
- 父块向量分数、子块向量分数、BM25 原始分数不能直接相加；沿用归一化加权思路，权重通过离线评测确定。
- 同一父块多次命中后只传一次正文。文档/版本/块 ID 应共同保证来源可追溯。
- 正式政策与心理支持知识做领域过滤；未来多校时再补充学校过滤。过滤需要同时覆盖向量和 BM25 路径。

### 6.4 对现有三个处理步骤的取舍

| 步骤 | 第一阶段建议 | 原因 |
|---|---|---|
| 分数融合 | 保留 | 仍有父向量、子向量和 BM25 多路候选，需要合并排序 |
| 本地规则重排 | 可选，保留开关用于对照 | 父子检索不依赖它；是否改善结果由评测决定 |
| 相邻块扩展 | 父子路径关闭，以父块取回替代 | 避免父块之外再次机械拼接，造成重复与预算膨胀 |

本地重排若保留，实施时需明确作用于父块归并前的候选，还是归并后的父块；默认值与位置通过对照评测选择，不同时堆叠多级重排。原有检索可作为开发对照，但不是新的默认路径。

### 6.5 预算、缺失资料与降级

- 分开配置候选数量、最终父块数量和正文 token 预算。
- 不直接沿用当前约 1200 tokens 的知识预算，先根据父块长度和模型窗口测量。
- 修复“首项过长直接停止、最终无正文”的行为；保留命中条款和必要条件，或选择其他可容纳且相关的父块，并记录裁减。
- 不为满足预算无提示地切掉决定答案的条件。资料不完整时应说明，而不是假装完整命中。
- 检索得分是相对相关性分数，不是正确率或答案可信概率。
- 无适用证据时不编造金额、期限和资格；条件缺失时只追问必要信息。
- 向量不可用时允许按配置降级到 BM25，并按相同父子关系取回父块；trace 明确记录实际路径。
- 引用必须来自实际选入的证据，不允许模型自行编造链接、条款号和页码。

## 7. 记忆与多轮状态

### 7.1 保留现有机制

- MySQL 保存完整会话消息和持久滚动摘要；Redis 为缓存及 Agent 私有备注提供支持。
- 普通累计摘要按会话维护；安全状态按用户维护，支持跨会话继承。
- 默认达到 12 条完整消息时压缩，目标保留最近约 8 条原文；正常稳定情况下约每新增两轮问答压缩一次。
- 压缩输入是“旧累计摘要 + 新移出消息”，不重复总结全量原文。
- token 压力可提前触发；摘要失败不推进覆盖游标，保留异步重试和调用前兜底。
- 每次用户消息创建新的运行与黑板，加载记忆重建上下文；不把上一轮任务板当作继续运行的状态。

### 7.2 面向校园资讯调整

- 摘要保留用户明确给出的身份、当前政策主题、已确认适用条件、未解决问题和条件变更。
- 用户最新明确更正优先于较早摘要，不把模型推测写成用户事实。
- 将“已尝试支持”等字段和提示词调整为兼容资讯问答，同时不破坏旧摘要读取；如改 schema，提供兼容策略。
- 检索改写使用近期原文和相关累计摘要，解决当前仅依赖近期概览导致较早条件丢失的问题。
- 记忆用于补全“那住宿呢”的主题；具体金额和现行规定仍查询政策资料。
- 第一版不额外构建完整业务状态机。先测试多轮追问、主题切换和条件更正，再判断是否需要轻量条件记录。
- 不额外承诺跨所有会话的通用用户画像或断点恢复执行能力。

## 8. 知识维护与数据迁移

- 从选定学校的正式文件起步，建立文件和版本清单。示例资料显式标注，不能混作正式政策。
- 优先支持可核对的文本/Markdown 和文字型 PDF；扫描 PDF、复杂表格的处理范围须明确，不把现有 pypdf 提取当作 OCR。
- 入库后可预览父块、子块和来源，人工检查关键金额、表头及例外条件。
- 文档更新时生成对应版本的父子块与向量，避免旧父块搭配新子块。
- 元数据、父子关系和索引应可重建；验证新索引后切换，失败可继续使用旧索引。
- 版本过滤和失效规则要同时用于父向量、子向量和 BM25。
- 当前 `create_all()` 不会补齐旧表列；新增字段需接入现有幂等列迁移或制定等效迁移方案，兼顾 SQLite 测试库。
- 调整启动默认知识导入逻辑，避免旧的平面切块导入覆盖已建立的父子结构。
- 旧心理知识保留到支持领域，旧消息、安全状态、报告和个案不做破坏性重命名或删除。

## 9. 学生端、管理端与可观测性

学生端：

- 更名和入口文案改为“校园有应”，提供政策咨询快捷示例，保留自然聊天。
- 回答展示可展开的文件来源、条款/页码、适用条件；无相关元数据时不生成虚假定位。
- 资料不足、需要补充信息、版本冲突分别自然说明，不显示内部风险等级和自报置信分数。

管理端：

- 保留安全状态、事件、报告、个案和工具记录。
- 补充知识文档、版本、领域和父子块预览，以及索引状态。
- 普通政策咨询与心理安全记录在展示语义上区分；不把所有 CONSULT 当作心理咨询量。

运行记录：

- 记录本轮意图、安全约束、查询改写和过滤条件。
- 记录父/子向量、BM25 各路命中及父块归并结果、实际提供给模型的证据。
- 记录降级、预算裁减、模型调用和检索耗时；保留既有安全审查与最终采纳过程。

## 12. 验收与离线评测

### 12.1 必测行为

| 场景 | 验收行为 |
|---|---|
| 普通闲聊 | 自然回答，不产生心理报告 |
| 明确政策问题 | CONSULT，命中适用文件并显示真实来源 |
| 金额、期限与例外 | 与条款一致，不遗漏改变结论的限制 |
| “那住宿呢”等追问 | 延续主题和身份，重新检索当前问题 |
| 条件更正与话题切换 | 更新适用条件，不沿用过期上下文 |
| 跨过摘要压缩边界的追问 | 仍能使用较早已确认的关键条件 |
| 知识库没有答案 | 明确资料不足，不编造标准 |
| 文件版本冲突 | 不混用不同版本，无法确定时说明 |
| 父块命中多个子块 | 最终正文去重，保留证据来源 |
| 首个父块超预算 | 不因直接停止而悄悄丢失所有可用证据 |
| 向量服务不可用 | 按配置降级，trace 反映真实路径 |
| 危险词的政策讨论、引用与否定 | 结合语境判断，与个人危险表达区分 |
| 明确危险表达 | 原有安全回复、同步风险保存和必要后续保持有效 |
| 高风险后改问政策/新开会话 | 未解除安全约束仍然生效，不重复滥发告警 |
| 重试、流中断和摘要失败 | 原有消息幂等、中断标识和摘要游标规则保持有效 |

### 12.2 评测方法

- 选择真实政策建立人工核对的标准问题、适用条件、证据条款与答案要点，不虚构报销金额。
- 调试集与未参与调参的保留集分开，覆盖有答案、无答案、例外、多轮和版本问题。
- 检索层对比现有平面切块、仅子块检索回父块、父子双向量混合召回，以及规则重排开/关；只做对判断有用的对照。
- 父子评测按文档版本和父块/条款标注，不能仅因命中同一文件就视为找到正确答案。
- 记录证据召回、排序、金额/条件准确性、引用有效性、无依据作答、多轮表现、耗时及模型调用成本。
- 原回答质量评测使用预设意图、风险和参考上下文，不能单独证明全链路正确；增加从输入到检索和生成的端到端验证。
- mock/harness 验证工程行为，真实 Embedding 与回答模型验证检索和语义效果；两种结果分别记录。
- 高风险与记忆回归继续执行。没有运行的评测不能写成已通过，不编造指标或预设提升结论。
- 数值验收门槛在基线和正式样本确认后制定；涉及关键金额、危险回应的失败必须逐例定位和处理。
