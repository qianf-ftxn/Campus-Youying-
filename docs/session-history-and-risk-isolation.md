# 历史会话与风险隔离修正

日期：2026-10-19。

## 学生历史对话

学生端侧边栏读取当前账号的历史会话，按最近更新时间排列，显示标题、时间和消息数；支持分页加载、切换、续聊和新建对话。刷新恢复本账号在当前浏览器标签页上次选择的会话。新会话在发送第一条消息时保存。

接口为 `GET /api/chat/sessions`（offset / limit）和 `GET /api/chat/sessions/{publicId}`。查询始终限定当前用户；访问他人会话返回 404。历史消息按原始顺序展示，中断回复标记状态；政策来源仅在管理端从当时的 trace 恢复，不使用当前知识库重新查询；学生端不返回来源。

发送过程中禁用会话切换与新建，防止流式回复串到其他窗口。

## 风险状态范围

- 同一个会话内：原有风险继承、保护因素检查、人工复核要求与分阶段降级继续生效。
- 同一账号的新会话：独立评估，不继承其他窗口的 HIGH、复核计数、风险事件或 Agent 私有记忆。
- 返回原会话：重新读取该会话的安全投影和消息，不因打开其他会话而清空原风险。
- 管理员解除、监测或误判操作：必须指定所属用户的具体会话，不再覆盖整个用户。

当前默认阶段阈值仍是：2 次有效安全复核从 ACTIVE 进入 MONITORING / MEDIUM，随后 2 次有效 LOW 复核将风险下限降为 LOW，再追加 1 次有效 LOW 复核解除。明确计划或准备行为导致的人工复核要求继续保留。普通话题切换不等同于有效安全复核。

`SAFETY_STATE_SCOPE` 改为 `session`。SQL 使用新表 `session_safety_states`，用户与会话联合唯一；Redis 使用 `mindbridge:safety-state:session:v2:{userId}:{sessionId}`。摘要中的安全事件引用也按会话过滤，旧用户级缓存不再读取。

## 旧数据兼容

原 `safety_states` 用户级表及所有消息、风险事件、报告、摘要、旧 trace 均保留。启动时按每个会话的原始风险评估与人工操作事件重建独立状态，忽略旧事件中包含其他会话风险的 effectiveRisk；不追加重复风险事件。完成标记允许迁移中断后恢复，不重复重建已完成会话。

历史回复继续显示原文；曾因旧用户级风险继承生成的回答不会被自动重写。后续评估与回复使用新的会话隔离状态。
