# 首轮检索问题定位（2026-10-30）

本文记录修复前的诊断与行号。父子切块现已修复，见 [当前修复结果](hierarchical-chunking-v2.md)；历史诊断JSON保留，当前诊断命令默认读取新版本试测报告。

结论：本批试测的主要丢失环节在**候选召回之后的融合排序与最终取材**；分块层级不充分、重复内容竞争、多轮评测查询构造也有影响。没有证据支持优先更换 Embedding 模型。

所有结论仍受25道待人工审核开发题的限制。下文的“证据”指当前标注的原文片段，未生成最终回答；诊断没有修改生产检索函数或生产索引。

## 1. 已定位的直接瓶颈：候选中存在，最终前4项没有带上

对混合检索的6道失败题，逐个追踪9个缺失标注片段：

- 9/9 都能在现有父块中完整定位，分块没有把这些标注片段彻底破坏。
- 9/9 都已进入父向量、子向量、BM25各取16项后形成的候选并集。
- 9/9 对应的可支持父块在最终融合结果中排第5～19位。
- 这6题的前4项没有因4000 token预算而被跳过，直接发生的是Top-K截断。

| 题目 | 缺失标注证据 | 融合后排名 |
|---|---|---:|
| X01：住宿申请是否替代实践备案 | 住宿办法第十六条；实践审批备案要求 | 10；6 |
| X02：休学助学金与离校手续 | 请假/报备审批与离校要求 | 14 |
| X03：学位证明书代办 | 申请材料；办理部门 | 10；9 |
| X04：外校修课与实践备案 | 实践审批备案要求 | 5 |
| X05：搬家与报备到期 | 住宿地点变更；到期前再次办理手续 | 19；15 |
| M04：更正境内自发修课 | 政治理论课须本校取得学分 | 5 |

生产实现位置：`app/services/knowledge.py` 的 `retrieve()` 先按归一化分数加权排序，再执行 `results[:top_k]`，没有检查多问题的必要信息是否覆盖，也没有语义冗余约束。

单因素诊断实验，固定现有切块、真实向量、查询、融合权重和4000估算token预算上限：

| 诊断变动 | 全证据题数/20 | 平均上下文估算tokens（20道可回答题） |
|---|---:|---:|
| 原始候选16、返回上限4 | 14/20 | 894.20 |
| 仅把返回上限改8 | 16/20 | 1603.45 |
| 仅把返回上限改16 | 19/20 | 2843.60 |
| 仅把每路候选扩大64，仍返回4 | 14/20 | 978.10 |
| 仅改RRF融合，仍返回4 | 14/20 | 907.85 |

| 仅加MMR冗余惩罚（0.7相关性/0.3冗余），仍返回4 | 14/20 | 947.85 |

这些是开发集上的局部干预，不是参数最优性搜索。返回16项的改善同时增加了实际上下文，不能视为免费提升，也不能直接改写成线上95%正确率。RRF和MMR在本次默认参数下没有增加完整题数，不代表它们在其他参数、数据上无效。

## 2. 结构性原因：父子层级经常退化为同一条款

固定49份启用文件生成1265个父块、1545个子块：

- 父块正文长度中位数86字符。
- 1122/1265（88.7%）父块只有一个子块，父子正文忽略空白后相同。
- 其中594组父子块的完整Embedding输入字符串也完全相同。
- 729/1265（57.6%）父块正文忽略空白后已经完整包含在其heading中；Embedding又使用 `heading + content`，同一条短规则重复出现。

代码在遇到每个“第X条”时直接开始新父块，子块又只在父块内部切。于是“父块1000、子块300”通常并不构成跨多个条款的层级；条款几十字长时，两路看见的事实几乎一样。这是实测结构特征，能解释互补性不足的风险，但还没有通过重新切块对照证明其单独造成多少损失。

另一个不一致是 `一、校外住宿手续`、`二、请销假手续` 等中文编号没有被当作主标题识别，而“第X条”却逐条拆开。`ygb-1061-9703` 的一个1015字符父块同时混入住宿、请假和校外实践三个主题。当前分块有的过细、有的跨主题，不能只把1000调大就解决。

相关代码：`app/services/knowledge.py:417` 的主标题正则及每次 `flush_section()`；`app/models/entities.py:118` 的Embedding文本拼接。

## 3. 排序机制偏向多路共同出现，不保证关键子问题覆盖

三路得分分别除以最高分后加权，未入某路前16的父块在该路得0分。两个高度重复的向量通道共同命中某条泛化规则时，可以压过另一路单独精确命中的限制条件。

X05的“到期前再次办理”条款是BM25第1名，得到BM25贡献0.35；但父向量排名21、子向量排名26，均在截断线外，两路贡献都是0，最终只排第15。它没有被关键词检索漏掉，而是在后续融合中失去名次。

X03的前4项则集中于多份文件里的“证明书同等效力”，材料与部门分别排第10和第9。按父块ID去重不能消除不同文件之间的语义重复，也不能确保“效力、材料、部门”各有证据。

向量分数变换还压缩了候选间差异：6道错题的父向量前16名，经当前分数变换和最大值归一化后，最低分约为最高分的90%～95%。这可能使“是否同时进入多路”更有影响；不过改原始余弦融合仍是14/20，因此不能把分数压缩单独认定为主因。

## 4. 上一轮评测也有问题：更正后的查询受旧历史干扰

M04历史是“学校组织境外交流”，当前问题明确更正为“自发去境内高校修课”。试测程序把两者直接拼接，混合检索的前4项仍包括境外交流与学校组织项目，遗漏政治理论课限制。

只为当前原始问题新增1个Embedding，保持检索算法、参数和候选语料不变：

- 拼接旧历史：2个标注证据只取回1个。
- 仅当前问题：2个标注证据都取回。

这证明该试测查询构造会影响这个案例。**不能据此认定生产ContextAgent改写失败**：生产的 `_rewrite_query()` 已通过模型要求“当前明确更正优先”，本轮没有执行该模型改写。这是上一轮评测简化带来的局限，必须在后续端到端评测中补齐。

## 5. 标注存在替代证据遗漏，不能把每个未命中都当成业务错误

X05被标注缺失“住宿地点变更须重新申请”，但其实际第1个结果 `ygb-1061-9703` 已写明“有效期内校外住宿地点变更的，须重新申请”。评分只认 `ygb-1061-13103` 指定原文，因此没有给这条等价信息计分。

这不代表X05整体应判完整：到期前再次办理手续的另一部分仍未取回。它说明当前按特定出处打分会把“有等价依据”误记为一项缺失。新旧文件的“有效期一年”和“不超过本学年”是否兼容，也应业务审核，不能凭同义词自动合并。

此外，X02把休学离校与普通请假/报备连在一题中，是否必须取回所标的整段请假条款才算足够，需要业务人员确认。部分标注片段还含未被问题询问的附加内容。应把答案拆成必要事实，为每个事实登记可接受的证据选项，并明确来源优先关系。

因此本轮先保留原标注与原分数，不因看到结果而静默补答案、删难题或发布所谓修复后的准确率。

## 建议修复顺序

1. **先修评测口径**：审核必要事实与等价证据；多轮增加生产改写查询评测，同时保留固定查询的检索消融，区分两个阶段。
2. **再修最终取材**：对已召回候选控制语义重复，按子问题保留证据；将返回数量与token预算结合，避免固定4个短父块占用完名额。Top-K=16先作为诊断上限，不直接上线。
3. **整理分块层级**：识别中文编号，保留章/主题与条款层级；对彼此关联的条件与例外建完整父块，子块保留定位粒度；避免把整段条款再次复制为标题。
4. **最后调融合参数**：在审核后的开发集上比较加权、RRF、冗余控制等方案，避免只凭本轮同分就选复杂实现。另建独立测试集验收最终回答。
