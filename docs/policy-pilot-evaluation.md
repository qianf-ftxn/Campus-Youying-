# 校园政策检索首轮试测

切块实现现为hierarchical-v2，当前结构、迁移规则及修复前后对照见 [层级切块修复](hierarchical-chunking-v2.md)。本文的数据审核与指标定义继续适用；新试测请输出到独立目录，保留旧报告。

后续开发基准已定为K=5，见 [基准说明](retrieval-baseline-k5.md)。下文K=4描述的是首轮固定对照；评测CLI未显式传入 `--top-k` 时跟随应用配置，历史对照需显式传4。

本轮目标是建立“带原文证据的开发集 → 三组检索对照 → 人工审核错例”的小闭环。它不能替代独立测试集，也不能证明回答的现行政策效力。

## 已交付内容

- `app/policy_eval/pilot.json`：25 道 AI 草拟题，每类 5 道，包括直接查询、条件与例外、跨条款、多轮、资料不足。所有题目的 `review_status` 初始为 `pending_human`。
- 20 道可回答题绑定原文引文、文件 ID、版本、内容摘要、字符位置、行号、官方来源链接、答案要点。5 道资料不足题记录缺失的资料或系统能力。
- `app/policy_eval/runner.py`：独立读取仓库快照，运行检索与原文覆盖评分，不连接业务数据库、Redis 或生产 Chroma，不生成回复、不执行预警工具。
- 自动导出原文审核表、匿名方案检索结果和机器报告。匿名结果是轻量人工审核辅助，不构成严格独立盲评。

## 数据范围与人工审核

语料固定为 `knowledge/xidian/manifest.json` 中 2026-10-19 快照在该日可用的 49 份 ACTIVE 文档。排除草稿、归档以及快照日期之外的生效/失效文件；manifest 与原文件摘要校验失败会终止，避免悄悄更换语料。

快照中的 ACTIVE 是仓库管理状态，不代表已经完成截至今天的制度有效性审查。旧版文件、旧金额、新旧专门办法的适用关系仍需业务人员核对。本轮没有访问官网重新核实现行政策。

先打开生成的 `annotation-review.md`，逐题核对：

1. **可回答性**：原文是否足以回答，是否需要用户进一步提供身份、年度或其他条件。
2. **证据范围**：必要条件、例外、适用对象是否全部标出；是否把无关整段纳入必要证据。
3. **答案含义**：答案要点是否超出引文；跨制度推断是否成立；原文是否存在冲突。
4. **多轮条件**：历史能否消解追问指代；当前更正是否应覆盖旧条件。
5. **资料不足题**：在整个固定语料中是否确实缺乏依据，而不是某次检索没找到。

在 `pilot.json` 中填写 `reviewer`、`review_note`，将 `review_status` 改为 `approved` 或 `needs_revision`。不要只因为系统命中了题目就批准标注。需要修改答案或引文时，应同时核对证据位置、版本和行号。

优先审核 C01（新旧请假规定）、X01/X04（实践与住宿/修课制度的共同适用）、M02（2019 年助学金标准快照），以及所有 U 类资料不足题。所有 25 题最终都需审核。

这些题目已经暴露给开发者并用于检查评分程序，全部属于 `pilot_dev`。审核通过后也不能改名为独立保留集。后续新建测试集时，同一问题的改写、同一对话的追问和同一证据族应归组，避免跨集合泄漏。

## 三组对照与固定条件

| 方法 | 召回与返回方式 |
|---|---|
| flat_vector | 普通 300 字符窗口，重叠 40，单路向量召回，直接返回小块 |
| parent_child_vector | 复用生产父子切块；父/子向量各取 16 个候选，子块映射父块，融合后返回父块 |
| parent_child_hybrid | 在上一组基础上增加子块 BM25，各路分别归一化，按 0.30/0.35/0.35 融合 |

所有组共用语料、Embedding 模型、查询和 Top-K=4、估算 token 预算上限 4000；关闭重排。双路向量组使用 0.30/0.35 并对活跃通道重新归一化。多轮查询统一拼接已有用户历史与当前问题，绝不使用标准答案或标注证据。

三组采用同一批真实 Embedding、精确余弦扫描；向量分数变换、父块归并与融合规则与生产实现保持一致，分块、BM25、归一化和 token 估算直接复用生产函数。这里没有运行生产 Chroma 的近似索引，因此是检索策略对照，不是线上性能验收。

相同预算是**相同上限**，不意味着各组实际上下文长度相同。报告必须同时给出上下文估算 tokens，避免把更多上下文带来的收益全部归因于排序。后续可以补固定实际上下文长度的敏感性实验。该估算复用项目启发式函数，不是供应商真实计费 token。

## 指标定义

评分先锁定文档 ID 与版本，再将取回正文定位到原文件。只忽略空白及父子切块移除的 PDF 页标记，不以标题、关键词或其他文件中的相同内容代替证据。重叠窗口按原文覆盖区间取并集，避免重复累计。

- **必要证据单元召回率**：每题完整覆盖的必要证据单元数 / 该题必要证据单元总数，之后按题宏平均。标注单元可能是一个条款或条款中的一个必要片段，并非统计全库所有相关块的传统 Recall@K。
- **证据完整率**：该题的所有标注必要证据单元均被完整覆盖才记为 1，之后按题平均。
- **证据命中率**：至少一个标注必要证据单元被完整覆盖的题目占比。
- `evidence_mrr`：累计到前 r 个结果时首次完整覆盖任一证据单元，取 1/r，再平均。这是明确定义的辅助指标，不是传统单块相关性 MRR。
- **上下文开销**：实际返回正文的启发式 token 估算值。主表按全部 25 题平均，分类表可单独查看。

上述检索效果仅在 20 道可回答题上计算。5 道资料不足题照常导出取回的资料，但“拒答正确率”保留 null；检索返回非空不能判错，返回空也不能判对。没有生成答案，因此回答正确率也保留 null。

本地耗时仅用于排查：不包含 Embedding API、余弦矩阵乘法、HTTP、模型生成，且 BM25 逐次分词，不能用它声称线上延迟改善、首字更快或高并发性能提升。

## 运行方式

在项目根目录执行：

```bash
# 只检查标注与文件哈希，生成审核表；不调用 API
.venv/bin/python -m app.policy_eval.runner --validate-only

# 离线 BM25 冒烟，只验证程序闭环；不冒充三组向量对照
.venv/bin/python -m app.policy_eval.runner

# 使用当前 .env 的真实 Embedding API，会产生接口调用
.venv/bin/python -m app.policy_eval.runner --real --output target/policy-pilot/real

# 评分与标注校验回归
.venv/bin/python -m unittest tests.test_policy_pilot -v
```

首次真实运行会向配置的 Embedding 服务提交 49 份公开资料的分块及 25 个查询。按相同接口/模型指纹与文本 SHA-256 缓存在独立的 `target/policy-pilot/embeddings.sqlite3`，每批提交可断点复用，不读取或改写生产索引。若供应商原模型名背后的版本改变，应使用新 `--cache` 路径，避免混用旧向量。

`target/policy-pilot/real/` 包含：

- `annotation-review.md`：人工核对题目、答案和原文。
- `retrieval-review.jsonl`：匿名方案取回的完整正文，人工结论预留 null。
- `report.md`：概要结果和需要检查的错例。
- `report.json`：语料/数据集指纹、配置、逐题证据覆盖及完整上下文，可复核统计。

首轮结果无论好坏都应保留。不要看完结果后只删除困难题或只保留有利参数；修订标注应说明原因、保存版本，并对所有方案重跑。完成这批题的人工审核后，再决定扩建独立保留集和最终回答评测。
