# 用户级长期记忆

2026-11-01 实施。普通会话摘要仍按 session_id 保存；新增长期记忆按 user_id 在本人多个会话之间复用，风险状态依旧按会话隔离。

## 已确认的产品规则

- 首期实现语义记忆和情节记忆。程序记忆复用现有版本化 Skills，不从聊天自动发布新流程。
- 每个完整回复保存后入队，后台判断用户消息是否值得记忆；允许下一轮暂未读到新记忆。失败重试，不阻塞 SSE。
- 使用相同规则一次性处理已有的完整对话。中断回复、未得到完整回复的消息不处理。
- 明确的新事实覆盖旧事实；假设、提问、第三方、过去身份不能直接覆盖当前身份。
- 不设统一保留天数。用户明确说出的完整截止日期到期后不再召回；完成事件仅在主动回忆时使用，不主动跟进。
- 不增加学生记忆管理页或正文查询接口。学生仅看到更新状态；管理员仅看到处理、检索、同步计数和错误类别。
- 校规、金额、制度答案不提炼为用户事实；普通长期记忆不接管安全状态。

## 存储和处理

`long_term_memories`：个人事实/经历、来源消息和会话、有效期、状态、修订号、索引修订号和 Embedding 指纹。

`long_term_memory_jobs`：每用户一个持久任务、目标消息 ID、处理进度、重试和检索统计。目标单调增长，运行时到达的新消息不会因任务结束而丢失。

`long_term_memory_extractions`：逐条来源消息的处理标记，包括没有候选的消息。它与记忆修改在同一事务提交；不靠单一最大游标跳过较早但后来才完成的消息。

Chroma：独立集合 `campus_personal_memory_v1_<fingerprint>`。复用既有 Embedding 接口和本地持久目录，不复用政策集合或其全量重建逻辑。MySQL 是权威数据；向量命中还要重新验证用户、修订号、有效期、状态。切换 Embedding 配置后检测指纹差异并重新索引。

已删除的记忆在 SQL 中立即停止使用、清空正文，后台删除向量。对话中明确说“清空我的长期记忆”或“忘记我的所有记忆”可清空已积累的长期记忆；不会删除原聊天记录，也不等于关闭未来记忆提取。清空边界阻止重放旧来源恢复已清空记忆。

语义字段：本人明确提供的称呼、学校、学历阶段、年级、专业、持续回答偏好和当前持续目标。首期对每个字段维护最新值；情节可保存多个事件。提取器只接收用户原文及有限现有事件，不接收助手建议作为事实来源。候选正文必须是当前用户原文的连续片段，模型改写或虚构证据不落库。事件可通过本人既有事件 ID 更新；补齐材料不等于整个申请已完成。

风险/健康/证件/学号等敏感内容和已有中高风险评估的来源轮次排除。提取前使用现有隐私脱敏。现有 Embedding 和模型均可能是外部服务，记忆处理沿用该配置，不会自动切换本地模型。

## 召回与上下文

在意图识别前读取少量相关用户背景；提到回忆、个人情况、持续事项或校园任务时检索候选，帮助理解跨窗口省略指代。问候或普通通用知识不调用向量检索，可读取回答偏好。检索失败时以同用户 SQL 记忆做有限词语匹配，状态标为 `LEXICAL_FALLBACK`；没有依据则不强行注入。

最多注入 4 条、1500 字（均可配置）。向量距离阈值是初始工程参数，不是事实置信度；没有把相似度当作正确率。少量个人背景不会挤占全部事件召回名额。当前输入的明确背景更正抑制对应旧背景；提示词要求当前和近期明确陈述优先于旧记忆。

个人记忆以带边界的数据块进入 UnderstandingAgent 和回答上下文。SafetyAgent 的风险评估不读取该块，不改变 current/carryover/effective 风险的作用范围。政策检索仍使用正式资料回答。

trace 落库前隐藏该个人记忆块，并隐藏使用个人记忆补全的检索查询；只保留运行状态和数量，不增加长期记忆正文接口。原有会话审阅仍会看到学生原话和实际回复，不改变既有权限。

## 启用、历史导入和故障恢复

配置见 `.env.example` 中 `LONG_TERM_MEMORY_*`。默认启用，Chroma 缺少连接/Embedding 时保留 SQL 记忆并后台重试索引。启动时创建新增表，启动长期记忆 worker；readiness 包含 `longTermMemory`。

一次性历史导入（服务启动后由后台处理）：

```bash
.venv/bin/python scripts/backfill-long-term-memory.py
```

服务尚未启动时，也可同步等待后台任务处理完：

```bash
.venv/bin/python scripts/backfill-long-term-memory.py --drain
```

不要让 `--drain` 与正在运行的应用 worker 同时处理同一批任务。脚本只输出数量；可重复执行，已处理消息不重复提取。规则调整后可用 `--recheck` 重新检查来源；它重置提取标记但不删除现有记忆，且保留用户清空边界。

学生：`GET /api/memory/status` 仅返回本人状态。管理员：`GET /api/admin/long-term-memory/status` 仅返回运行元数据，后台页面可刷新查看。

模型提取失败：事务回滚、保留进度，按配置重试，达到上限标记 DEAD；可重新运行历史入队脚本恢复任务。向量同步失败：保留 SQL 权威记忆，标记 DEGRADED，后台间隔重试；不重复调用提取模型。

个人数据位于数据库及 `data/chroma`，不提交 Git。公共官方 RAG 文档仍随仓库保留。

## 验证

自动测试见 `tests/test_long_term_memory.py`：事实覆盖/假设/原文依据、用户隔离、事件完成与有效期、索引修订与模型切换、重试与原子回滚、运行时新增任务、断线排除、真实本地 Chroma 过滤、跨窗口注入与 trace 隐藏。前端状态测试见 `tests/student_memory_status.test.cjs`。

真实模型验证使用隔离 SQLite 和临时 Chroma 目录，测试数据未写入业务会话；记录仅在忽略目录 `target/long-term-memory/`。有限样例通过不代表覆盖所有自然语言；首期保守提取，宁可不存，也不将推测或敏感内容固化为个人事实。

## 2026-11-01 自查修复

- 入队以数据库实时状态判断，不依赖已缓存的 ORM 状态，避免任务结束与新消息入队交错时留下 SUCCESS 假象。
- worker 启动及运行中每 60 秒扫描已完整保存、尚未提取的现代对话回复，补偿回复保存后入队失败或进程中断；不自动清除 DEAD 失败计数。旧版无父消息关联的历史仍用显式导入。
- 后台每 60 秒核对个人 Chroma 集合中真实 ID、修订和状态；即使 SQL 记录显示已同步，也能修复丢失的索引。修复失败保持待同步状态。
- 无效日期或候选字段类型只丢弃对应候选，不阻塞同轮其他有效事实；新学籍状态如已毕业、结业、休学、退学可抑制旧背景。
- 向量功能主动关闭时不显示同步故障；临时索引故障恢复后，学生端状态继续轮询更新。
- 事件原文仍明确包含“未完成/尚未/没通过”等表述时，不采纳模型的 COMPLETED 标签。
