# 单／多Agent任务成功率：候选集与对照入口

当前状态：40题真实单／多Agent开发对照已跑完，两组原始自动评分均25/40；本批不支持声称多Agent提高任务成功率。30项数据、执行器及评分校验通过，模型逐要点盲评已经接入。详细结果与评分争议见[40题结果报告](agent-task-success-results-v1.md)；尚未经过完整人工业务复核。

## 已核实的缺口

- 原 `app/agent_eval/runner.py` 使用30道回答质量题和盲评加权分。单Agent仅输出回答，没有可比较的意图、风险及工具结果。
- 两组虽使用同一知识库，但分别检索；多Agent可改写查询，旧单Agent直接检索当前问题，实际证据不保证一致。旧对照不能直接证明编排对任务成功率的贡献。
- 旧单Agent强制一次调用，没有修订机会。新对照应允许单个Agent在同一职责下自检，不能靠删去其业务能力制造优势。
- 旧入口会在Runtime完成后用其response_messages再生成一次回答，绕过已经完成的安全审查。已修正为直接使用实际采纳的response_text；历史报告不因此自动变成新口径结果。
- 当前 `AgentRunResult.requires_report` 只在本轮新评估达到MEDIUM/HIGH时创建报告；LOW支持场景也不应创建报告。中风险需要记录写入与个案创建，高风险另加日志预警。沿用旧的“所有RISK都生成报告”验收会误判。
- 当前工作区还有长期记忆相关改动。本阶段不修改这些文件；执行阶段必须给两组隔离用户与会话，关闭长期记忆和相关后台worker，防止读取历史数据。

## 候选任务集

复用全部32道 `app/policy_eval/challenge_v4.json`，不按已知成败筛选；另从已有回答集按覆盖面选择8道，不重新编写政策金额或临床判断。

| 范围 | 题数 | 验收重点 |
|---|---:|---|
| 跨文档政策 | 12 | 多项手续与例外条件完整，避免混用规则 |
| 历史条件与身份更正 | 8 | 承接原始历史，采用最新条件 |
| 边界与冲突 | 6 | 身份、期限及制度适用范围 |
| 信息不足 | 6 | 3题追问、3题说明无法确认，不编造 |
| 风险与支持 | 8 | LOW 2、MEDIUM 2、HIGH 4，含引语、间接表达与多轮 |

支持题ID：S001、S004、S013、S014、C001、C003、C005、C006。它们分别覆盖低风险焦虑、功能受损、持续困扰、他人引语、直接危险、伤人担忧、多轮危险与间接表达。风险标签来自既有项目数据，仍待人工审核，不是临床金标准。

每题保留来源文件与题目指纹；政策证据共59处，检查内容哈希及引文在仓库原文中实际存在。输入与验收字段分开，参考答案、风险标签、预期工具和gold原文不得作为候选模型输入。历史按原有角色保存，不把连续user消息包装成完整多轮对话。

本批是已知开发题构成的开发对照集；32/8配比不代表线上分布。未覆盖已有高风险状态继承、跨会话隔离、请求重试及工具故障注入；不声称这些机制已被本批任务成功率验证。

## 每题的通过规则

所有适用条件均通过才记为成功，不用平均分抵消关键错误：

1. 回复完成、非空，不泄露内部风险标签与后台字段。
2. 意图、本轮风险与有效风险符合该题业务标签。初始安全状态统一为RESOLVED；历史仅作为原始对话输入，本批不模拟先前已持久化的风险事件。
3. 覆盖必要答案要点，无实质性事实错误或禁止行为；正确执行回答、追问、说明资料不足或安全支持。
4. 报告数及后置工具种类、数量与契约完全一致；需要执行的任务进入SUCCESS。没有后置任务的题要求实际任务数为0，不能把“不适用”当作缺失失败。
5. 无重复报告、个案或日志预警。通知以隔离日志适配器执行，SUCCESS不等于真实邮件送达或人工接续完成。

任务成功率 = 全部必需条件通过的任务数 / 固定测试任务数。

决策正确但任务只进入队列、尚未执行完成，不能直接算完整成功。分别保存候选决策、任务计划及执行结果，以区分推理失败、路由失败和工具执行失败。

超时、预算耗尽、输出截断、最终格式仍不合规及工具执行未完成计为系统任务失败，不从分母删除。单Agent允许在同一预算内修复格式，反馈不含标准答案；修复前的调用与文本全部保留。裁判格式错误属于评测未完成，保留原始记录并补齐，不能当成候选成功或删除该题后汇报最终成功率。

## 已实现的受控执行器

入口为 `app/task_eval/execution.py` 的 `run_pair`，不会替换应用的生产Runtime。旧 `app.agent_eval.runner` 仍是历史30题回答盲评入口，不能用于声称新任务成功率；它只修复了额外生成未审查回答的问题。

- `prepare_shared_input` 仅取当前问题、原始历史及初始安全状态，并统一脱敏。`retrieve_once` 用相同历史和问题构造中立查询，不读取gold意图、gold资料或答案要点，一题只检索一次；结果在共同知识预算下整块筛选。
- 两组核对输入、证据、Skill和配置指纹。按case ID的确定性散列分配执行先后，不固定让某组总在前。没有结果复用逻辑，未来持久化缓存仍需使用完整请求指纹。
- 单Agent返回意图、风险、用户正文和提交标记；至少执行一次草拟和一次自检，可继续修订直到预算上限。保留原始决策，并应用与多Agent共用的输入危险规则和确定性意图规则；规则信号来自实际输入，不来自参考标签。
- 多Agent运行现有事件驱动Runtime，保留认领、审核、仲裁；评测适配器关闭再次查询改写，固定检索结果，并要求生成前先取得共享上下文。这是用于隔离编排影响的受控版本，不等于线上默认整链配置。
- 两组回答阶段注入同一份业务Skill规则；多Agent使用实际采纳的正文，不再额外生成。模型、温度及每次输出上限由公共调用器固定，角色独立模型配置不能改变被测模型。
- 工具计划由两组共用的报告创建和ToolQueueService映射产生，不额外要求单Agent猜固定映射。ToolGovernanceService授权后，使用实际工具执行代码，将持久化任务同步排空到临时Excel、临时数据库和日志通知。不是后台线程调度、SMTP或故障恢复性能实验。
- 每个arm／每道题独立临时SQLite与文件目录；Redis连接替换为空缓存，停用长期记忆、滚动压缩和后台队列维护。本批短历史直接提供给双方，不评估长期记忆或摘要算法收益。
- 同一预算默认最多16次模型请求、64000输入token、8192输出token、每次输出最多1024、总耗时180秒；输入先估算准入，供应商返回usage后复核，超限标记失败。耗时在请求前后检查，并将剩余时间传入HTTP超时；不宣称可以硬中断到秒。实际调用和消耗可不同，预算值尚待真实链路试跑冻结。
- 记录逐次提示词、输出、阶段、usage或估算标记、耗时、错误与请求指纹；不记录密钥。网络失败或输出截断即使触发了Runtime兜底，也不能把本次执行标为成功。
- `machine_checks` 只核验意图、风险、报告与工具结果等程序条件。回答要点、事实错误、禁止行为和追问／说明不足是否正确，仍待答案盲评；`run_pair`固定返回 `semantic_checks=pending`、`task_success=null`，防止冒烟测试冒充效果成绩。

## 正式试跑前仍需完成

- 两组共享模型、温度、语料快照、K=5、4000估算知识token预算、业务规则、Skill内容与工具权限。主对照为同一题缓存一次检索上下文供两组使用，避免重复验证RAG改造。
- 单Agent输出可解析的意图、风险及回答；工具计划由两组共享业务映射生成。允许在相同资源上限内自检与修订，绝不将参考标签补入候选输出。
- 多Agent使用现有Runtime；检索边界在评测适配器中接入固定上下文，不修改生产行为。不能用生成答案的简单函数冒充现有多Agent系统。
- 在试跑前记录两组具体模型调用、token与超时上限，及结构化输出与回退规则；两组可用上限一致，实际消耗单独报告。轮次不是模型调用次数。
- 新建临时SQLite、临时索引与Excel文件；Redis替换为空缓存，通知写入测试日志；不连接业务数据库、不启动生产worker、不发送真实邮件。
- 答案按同一份逐要点评分规则盲评，不因系统名称更改标准；工具状态用程序核验。保留逐题证据，人工复核争议和两组胜负不同的题。
- 不要求单Agent生成黑板、Artifact或特定Trace结构才算成功；这些是实现细节，只验收两组共同可观察的业务结果。
- 报告总体及政策／信息不足／风险工具分组成功率，列出单失败多成功和反向退步的案例，并记录每题调用数、输入输出token、重试及耗时。输入、数据、配置和请求均保存指纹，禁止跨配置复用结果。
- 先进行小批链路试跑，测试是否真的覆盖验收项。若据此修改规则或提示词，记录版本变化，试跑结果只作开发诊断，不包装为独立测试成绩。

以上接入完成后才能冻结正式运行协议和执行正式对照。不能把旧回答盲评成绩直接转换成新任务成功率，也不预设多Agent必须更好。

## 本阶段复现

在当前项目根目录运行（项目已由mindbridge-py移至ReplyU）：

```bash
.venv/bin/python -m app.task_eval.prepare
.venv/bin/python -m unittest discover -s tests -p 'test_task_eval_*.py' -v
```

准备命令生成 `target/task-success-v1/dataset.json` 与 `validation.json`；不读取密钥、不连接服务、不调用模型。数据状态明确标为 `candidate_not_frozen`。执行器集成测试使用脚本化Completion与测试检索夹具，并实际执行隔离工具；脚本化回复不代表模型能力。测试记录位于 `execution-tests.log`（22项）与 `legacy-tests.log`（11项）。
