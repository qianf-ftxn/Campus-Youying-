# 校园有应：项目简历文案

以下按大模型应用开发方向组织。使用“实现/完善”描述已经存在的功能，不虚构项目起止时间、团队规模、个人职务或线上使用量。

## 可直接调整使用的投递版

**校园有应｜多Agent校园咨询与知识问答系统**

项目简介：面向校园政策咨询与多轮交流，实现意图路由、知识检索、上下文记忆和安全支持，提供SSE流式对话及管理端证据溯源。

技术栈：Python、FastAPI、SQLAlchemy、MySQL、Redis、Chroma、SSE、Docker。

- **多Agent编排与Harness**：实现统一运行底座，集中管理输入脱敏、上下文注入、消息持久化与Trace；通过共享任务板、Artifact及任务认领协调理解、安全、检索与生成，设置8轮协作预算；基于clientMessageId和数据库唯一约束实现请求幂等，复用重试请求的已完成回复。
- **结构化RAG检索**：面向49份启用制度资料，按章节聚合父块、按条款拆分子块并保持表格完整性；构建父/子向量与子块BM25三路召回、加权融合及可选LLM语义精排，以Top-5父块和4000估算token知识预算筛选完整证据，改善表格截断与适用条件缺失问题，支持向量故障时降级至BM25。
- **上下文与记忆一致性**：采用MySQL权威存储与Redis缓存，构建会话级MemorySnapshot及滚动摘要；完整消息达到12条时触发压缩、目标保留近期8条，摘要经结构及600估算token校验后，通过版本乐观锁更新覆盖游标；失败保留旧状态，按会话隔离记忆与安全状态，降低并发覆盖和跨会话污染风险。
- **版本化知识与证据溯源**：按学校、业务域、状态及有效日期过滤文档，显式版本不可覆盖；以模型指纹隔离向量索引，新collection构建校验后原子切换manifest，失败保留旧索引；将回答与当次实际证据原文、文档版本及章节绑定，避免知识更新后历史来源漂移，支持管理端问题追溯。
- **消融实验与效果验证**：固定模型、回答提示词及K=5，完成“平面/父子索引×是否精排”四组消融；在32题复杂场景开发回归的自动评测中，相较原始平面工程，将26道可答题的参考要点符合数从19/26提升至24/26、指定证据齐全题数从13/26提升至24/26，Faithfulness从0.683提升至0.771。

投递版仍可按页面空间压缩；每条保留一个主要问题、一组关键机制及必要数字，不需要加入所有配置参数。

## 面试时应能解释的设计

1. **Harness与Coordinator职责不同**：Harness处理单轮输入准备、持久化、上下文和追踪等运行事务；Coordinator组织Agent任务与产物，管理协作预算和最终采纳。
2. **记忆的价值在一致性与隔离**：摘要保留身份、业务主题与条件更正；以会话为范围，使用快照、版本和覆盖游标控制更新。历史回答中的政策结论不能替代当轮适用知识。
3. **证据溯源绑定当次实际上下文**：文档更新以后，历史消息仍显示当时提供给模型的资料，不重新用当前索引伪造旧答案的来源。
4. **RAG收益需要分开归因**：统一300/40控制组中，平面15/26、父子19/26、平面加精排24/26、父子加精排24/26。父子结构在无精排时有收益，精排后提高指定证据完整性，但本批回答符合数未进一步提升。
5. **效果与开销存在取舍**：父子加精排的推理输入token约为平面加精排的1.48倍，不宣称同时更准更省。原始512/64工程19/26与统一300/40控制组15/26是不同基线，不能混报提升幅度。

## 指标与实现口径

- 32题是已知复杂场景开发集，包含26道可回答题及6道资料/条件不足题；当前仍为AI标注和模型评分，待人工业务审核。
- 19/26→24/26为73.08%→92.31%，提高19.23个百分点；使用“参考要点符合率”而非未经确认的线上准确率。
- Faithfulness是回答政策事实得到实际上下文支持的模型评分，不等于人工事实正确率或直接测得的幻觉率；这些结果见同批32题的原始平面工程与`rerank_only`对照。
- 多Agent为事件驱动协作，不宣称已实现多模型并行加速；运行Trace是追踪记录，不是进程中断后的执行检查点。
- 记忆为会话级，不描述为已经上线的跨会话长期用户画像。
- 语义精排功能已经实现并完成离线试验，但默认开关仍关闭；邮件当前为日志投递模式。限流和超时为机制配置，不描述为线上吞吐或延迟实测。
- 本项目基于既有MindBridge实现改造；个人贡献应按实际负责范围调整，不把未参与实现的模块写为从零独立研发。

指标与实现依据：

- `docs/rag-core-ablation.md`：固定四组消融、配对改善与退步、开销。
- `docs/policy-diagnostic-v4.md`：同批复杂题的Hit/MRR、Faithfulness、Answer Relevancy及评分限制。
- `app/agents/harness.py`、`app/agents/coordinator.py`：运行底座和任务调度。
- `app/services/memory_context.py`：摘要校验、快照、版本与游标。
- `app/services/vector_store.py`、`app/services/conversations.py`：索引切换及历史证据恢复。
- `app/services/tool_queue.py`、`app/services/tool_governance.py`：任务重试、限流、死信与授权审计。
