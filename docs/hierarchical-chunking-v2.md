# 层级切块修复（2026-10-30）

本轮修复父子切块与旧资料迁移。检索候选数16、最终Top-K=4、4000估算token预算、向量模型和融合权重均保持原配置，以便单独观察切块变化。

## 行为变化

旧实现每遇到“第X条”就开启一个父块，再把这一条切成子块，导致大部分父子正文重复。新实现为：

1. 识别Markdown标题、“第X章/节”、“一、”“（一）”等主题标题并维护祖先路径。识别中文编号标题时使用长度和句末标点约束；条款内部的枚举条件留在该条中。
2. 将同一章、节、主题内的相邻条款组织为父块，按1000字符目标分组。超长正文优先按完整句子拆分；表格作为整体，允许超过目标长度。
3. 子块按父块内的具体条款、步骤或段落组织。大于300字符的正文优先按句子拆分；重叠保留不超过40字符的完整尾句，单个超长句使用300/40字符滑动窗口。
4. 标题使用文件名、章/节/主题路径与条款编号范围，不再把整段条款正文当成标题再复制一遍。子块标题补充自己的条款编号。
5. 短而独立的完整主题仍允许一个父块对应一个子块，不为追求比例而机械拆碎。PDF记录父块起始页；不提供OCR或复杂PDF表格重建。

例如“第二章申请审批”中的第四至第七条，共同组成一个父块，各条款分别成为子块。住宿、请假、校外实践三个中文编号主题会分别形成父块。

实现位于 `app/services/knowledge_chunking.py`；导入、迁移及检索仍由 `app/services/knowledge.py` 负责。

## 旧资料库如何生效

`knowledge_documents` 新增 `chunking_version`，签名同时包含算法版本与父块长度、子块长度、重叠配置。MySQL和已有SQLite都支持幂等补列。

启动流程完成资料接入后自动执行 `rechunk_documents()`：

- 从原始文档正文重新生成当前代父子块，文档ID、内容、来源、版本、启用/归档状态保持不变。
- 在单次SQL事务中切换块类型；旧块改为 `retired_parent` / `retired_child`，保留ID和正文，检索及默认预览只使用当前代。迁移失败回滚全部变动；重复启动不重复创建。
- 迁移会锁定需要更新的文档，避免MySQL多进程重复切代。
- 迁移不直接覆盖旧向量集合。下次向量检索检查块ID和内容摘要，按已有staging机制完整构建新集合后切换；管理员“重建向量”也会先检查切块版本。
- 若向量重建失败，旧集合指针保留，但旧ID不会被当作新代候选使用。optional模式使用新SQL块的BM25；required模式按原配置返回向量不可用。

旧代迁移属于结构更新，不是新的政策内容版本。历史消息来源已按生成时内容保存，退休块保留供审计。运行中的旧后端需正常重启加载新代码；本次没有直接操作本机业务数据库或替用户启动服务。

管理端状态接口新增当前切块版本、待迁移文档数、退休块数。文档预览仅显示当前代，避免把退休块混入新的父子结构。
