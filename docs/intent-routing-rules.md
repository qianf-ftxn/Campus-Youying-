# 意图路由规则

更新：2026-10-19。业务意图仍为 CHAT / CONSULT / RISK；RISK 表示需要情绪或安全支持，不等于 HIGH。

## 规则与语义判断顺序

1. 明确现实危险信号先进入 RISK，区分否定、引文、概念讨论与真实求助。
2. 明确的现实情绪困扰或倾诉需求进入 RISK；不根据“压力”“焦虑”“崩溃”单词直接判断。
3. 需要本校权威事实的规定、资格、金额、期限、办理流程、限制或联系信息进入 CONSULT。
4. 没有情绪求助和政策事实需求的明确闲聊、分享、通用知识、写作、翻译或编程进入 CHAT。
5. 短追问只有在当前政策话题连续且业务对象或指代明确时，才由规则继承 CONSULT。最多回看最近六条用户消息；遇到话题切换停止，旧摘要不单独触发继承。
6. 其他或规则不能确定的输入返回内部 UNKNOWN，结合上下文交给现有 UnderstandingAgent 的分类模型。提示词统一要求仅输出标签；解析层接纳完整的 CHAT / CONSULT / RISK 标签（忽略首尾空格和大小写），也兼容完整 JSON 对象中的合法字符串 `intent` 字段，不再次用规则覆盖 CONSULT。不从解释文字或代码块中提取标签。

UNKNOWN 不进入业务枚举、前端或数据库意图字段。模型失败或输出不是完整合法标签时，业务意图降级 CHAT；SafetyAgent 独立的输入风险评估、会话风险继承与降级规则仍执行。

## 边界样例

| 输入 | 预期意图 | 说明 |
|---|---|---|
| 什么是奖学金 | CHAT | 通用概念 |
| 西电奖学金申请条件是什么 | CONSULT | 本校资格条件 |
| 帮我写一封请假邮件 | CHAT | 纯写作 |
| 按学校请假规定帮我写邮件 | CONSULT | 先检索规则，再组织邮件 |
| Java课程补考怎么申请 | CONSULT | 编程语言名称不取消业务请求 |
| 报销系统的代码怎么写 | CHAT | 开发系统不等于查询制度 |
| 报销完了好开心 | CHAT | 分享已完成的事情 |
| 报销到账了，下次需要哪些材料 | CONSULT | 分享之后仍有新的事实问题 |
| 电吹风能带回寝室不 | CONSULT | 规则不确定时交给模型判断口语中的校内限制 |
| 门禁到啥时候才开 | CONSULT | 服务开放时间，允许语义兜底 |
| 压力测试怎么做 | CHAT | 技术任务 |
| 帮我写一篇关于焦虑的论文 | CHAT | 讨论情绪概念不是本人求助 |
| 最近压力很大，想找人聊聊 | RISK | 现实情绪求助 |
| 我想自杀 | RISK | 风险等级由独立安全链路评估 |
| 差旅咨询后“那住宿呢” | CONSULT | 连续业务追问 |
| 政策咨询后讲笑话，再问“那住宿呢” | 由模型判断 | 不由旧政策关键词强行继承 |

无对应文件仍为 CONSULT，由回答层明确说明缺少适用资料，不改成 CHAT，也不编造金额或条款。多意图消息包含明确现实危险/情绪求助时，优先支持与安全；其他混合任务按是否依赖学校权威事实决定是否检索。

## 后台定位

UnderstandingAgent 的 intent 产物包含 `routingSource`（rule / model / fallback）、`ruleId`、`modelLabel`（解析后的合法模型标签）、`fallbackReason`、`reason`、`requiresPolicyRetrieval`。无效模型输出只记录错误类别，不将任意模型文本用作标签。它们随原有管理端 trace 保存，不新增学生来源展示或审核 Agent。

回归覆盖见 `tests/test_intent_rules.py` 与 `tests/test_true_streaming_and_routing.py`。自动测试与有限真实模型样例不代表覆盖所有自然语言；后续可把实际误判纳入独立离线样本集。
