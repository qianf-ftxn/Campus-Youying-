# 当前开发基准：Top-K=5（2026-10-30）

后续检索与问答对照固定采用当前hierarchical-v2父子块混合检索，最多返回5个去重后的父块。K表示最终结果上限，不是每路候选数量，也不要求每个问题必须凑满5块。

## 固定条件

| 条件 | 当前基准 |
|---|---|
| 最终返回上限 | 5个父块 |
| 候选数 | 父向量、子向量、子块BM25各16项 |
| 知识预算 | 4000估算tokens |
| 切块 | hierarchical-v2；父1000、子300、重叠上限40字符 |
| 融合权重 | 父向量0.30、子向量0.35、BM25 0.35 |
| 重排开关 | 关闭；不得把本地规则重排描述为神经重排 |
| 本轮Embedding | 当前配置的text-embedding-v4；模型/接口指纹写入报告 |
| 开发语料 | 2026-10-19仓库快照中49份启用文档 |
| 开发题目 | 原25题，20道可回答题参与检索召回；5道资料不足题另行评价 |

默认设置、`.env.example`、本机`.env`和README已同步为5。评测CLI省略 `--top-k` 时读取当前配置；显式传4仍可复现历史对照。运行中的服务需重启后读取新的配置。

Top-K不参与切块签名，也不改变已有向量，因此单独从4改5不需要重新切块或重建索引。此前hierarchical-v2的结构迁移仍按其既定规则执行。

## 为什么不同时增加候选或token预算

K=5试测中25个场景均在4000上限内返回5块，最大上下文约2780估算tokens，平均2015.72。当前没有因这次增加一块而必须提高预算的证据。

候选仍保留每路16。此前错例已经显示关键证据可能在候选池中被排到后面；增加最终返回上限不要求候选按比例增加。长度、模型、融合和重排也保持一致，否则难以区分收益来自哪项修改。

## 尚未解决的问题

1. 本批20道可回答题中仍有X01、X02两题没有取全全部标注证据；其中跨制度适用和替代证据仍需人工审核。
2. 资料无答案时不能把取回5块当作有答案；5道资料不足题的正确拒答尚未测。
3. 更多上下文也会增加阅读负担和潜在干扰。当前只验证了检索证据，Faithfulness、Answer Relevancy、最终答案正确性和真实生成延迟尚未完成。
4. 4000是硬预算上限，不保证未来所有问题都能放入5块。超预算时继续按既有规则跳过，报告应记录实际提供的块数和token估算值。
5. K=5由这批开发题选择而来，它们已不是独立测试集。不能将95.83%的开发集证据召回率当作最终回答准确率或独立泛化成绩。

后续先保持这些条件固定，审核标注并补生成层评测；需要改变模型、切块、权重或语料时，另开实验版本，同时保留K=5基准结果。
